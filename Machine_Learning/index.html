Foundations

What is Machine Learning?

Machine Learning (ML) is teaching computers to learn patterns from examples instead of following rules a human wrote by hand.

🧑‍💻 Traditional programming

Rules (written by a human)
+
Data
↓
Answers

"If the email contains 'FREE MONEY', mark it as spam." — works until spammers write "FR33 M0NEY".

VS

🤖 Machine Learning

Data (examples)
+
Answers (labels)
↓
Rules (a "model")

Show the computer 100,000 emails already labelled spam / not spam, and it figures out the patterns itself.

Think of teaching a child what a dog is. You don't give them a rulebook ("four legs, fur, tail…" — a cat has those too!). You just point at many dogs and say "dog". Eventually they recognise dogs they've never seen before. That's exactly what ML does — and that last part, working on new, unseen examples, is the whole point.
📦

Data

The examples we learn from. Like a textbook full of solved problems.

⚙️

Model

The "pattern" the computer learned — a mathematical recipe that turns inputs into a prediction.

🔮

Prediction

The model's answer for a new input: "this house is worth ₹85 L", "this email is 97% likely spam".

The 3 (+1) ways machines learn

The main difference is what kind of feedback the computer gets while learning.

👩‍🏫

Supervised Learning

Learning with an answer key. Every example comes with the correct answer (a "label").

  • Regression — predict a number: house price, temperature, sales next month.
  • Classification — predict a category: spam / not spam, cat / dog, will a customer leave?

≈ 80% of ML in industry is supervised.

🔍

Unsupervised Learning

Finding structure with no answer key. The computer groups or simplifies data on its own.

  • Clustering — group customers into "segments" with similar habits.
  • Anomaly detection — spot the one weird transaction among millions.
  • Dimensionality reduction — summarise 100 columns into a few.
🎮

Reinforcement Learning

Learning by trial and error. An "agent" takes actions and gets rewards or penalties.

  • Game-playing AIs (AlphaGo), robots learning to walk.
  • Fine-tuning chatbots to be helpful (RLHF).
📚

Self-Supervised Learning the "+1"

The data creates its own answer key. Hide a word in a sentence and learn to guess it.

  • This is how Large Language Models (GPT, Llama) are pre-trained on the internet's text.
Supervised = studying with a teacher who marks your answers. Unsupervised = sorting a messy drawer into piles without being told the categories. Reinforcement = learning to ride a bicycle: nobody gives you the answer, you just fall (penalty) or don't (reward).

Data: the fuel of every model

"Garbage in, garbage out." A simple model on clean data almost always beats a fancy model on messy data.

📥

Collect

Databases, CSV files, APIs, web scraping, sensors, surveys. Ask: is it legal, unbiased, and representative?

🧽

Clean

Fix missing values, remove duplicates, correct typos and impossible values (outliers), unify formats.

📊

Explore (EDA)

Charts & summaries to understand the data: distributions, correlations, surprises. "Interview your data."

🛠️

Engineer features

Create better clues: price_per_sqft, distance_to_metro, turn "Location" text into numbers.

Splitting the data — the most important habit

Training set · 70% — the model studies this
Validation · 15%
Test · 15%

Training = the textbook. Validation = practice tests used to tune the model. Test = the final exam, opened only once at the very end.

Data leakage: accidentally letting the model peek at information it won't have in real life (e.g. including "final sale date" when predicting whether a house will sell). The model looks brilliant in testing and fails in production.

Interactive Demo · Step 7–8

Underfitting, overfitting & the sweet spot

A model must be complex enough to capture the pattern, but not so complex it memorises the noise. Slide the complexity and compare training error with test error (new data).

● training points ● test points (unseen) — model

Scores

Training error—
Test error (what really matters)—
😴 Underfitting — too simple. Bad on training and test. Like a student who didn't study.
🎯 Good fit — captures the real trend. Good on both.
🤓 Overfitting — memorised the training data including its noise. Great on training, poor on test. Like a student who memorised last year's answers but can't solve new questions.
  • Fixes for overfitting: more data, simpler model, regularization (penalising complexity), cross-validation, early stopping, dropout (for neural nets).
  • Fixes for underfitting: a more complex model (higher polynomial degree, deeper trees, more layers), better or more informative features, less regularization (smaller λ / alpha), longer training, and removing noise or errors from the data.
Interactive Demo · Step 8 Evaluation

Is the model any good?

Our spam filter gives each email a spam score from 0–100. We choose a threshold: above it, the email goes to spam. Move the threshold and watch the trade-off.

😈 = actually spam · 🙂 = actually a real email · red border = sent to spam folder · number = model's score

Confusion matrix

Metrics

Accuracy — % of all calls that were right
Precision — of emails flagged, % truly spam
Recall — of all spam, % we caught
F1 score — balance of the two
Precision = "when I raise the alarm, am I right?" Recall = "did I catch all the bad guys?" A high threshold is cautious (high precision, low recall). A low threshold is paranoid (high recall, low precision).

Which metric for which problem?

Problem typeCommon metricsPlain English
Regression (house price)MAE, RMSE, R²"On average, we're off by ₹4 L." R² = how much of the variation we explain (1.0 = perfect).
Classification (spam)Accuracy, Precision, Recall, F1, ROC-AUCAccuracy is misleading if classes are imbalanced: if only 1% of transactions are fraud, "never fraud" is 99% accurate — and useless.
Medical screeningRecall firstMissing a sick patient is far worse than a false alarm.
Recommendations / searchPrecision@K, NDCGAre the top 10 results actually relevant?
LLM appsHuman ratings, LLM-as-judge, groundednessIs the answer correct, relevant and based on real sources?

Deep Learning & Generative AI

Deep learning powers today's AI boom. AI Engineers mostly build products on top of large pre-trained models rather than training them from scratch.

🕸️

Neural networks

Inputs flow through layers of tiny calculators ("neurons"). Early layers detect simple things (edges), deeper layers combine them into complex ideas (eyes → faces). "Deep" just means many layers.

💬

Large Language Models

Neural nets trained on huge amounts of text to predict the next word. Do that well enough at scale, and the model can write, summarise, translate and reason. Examples: GPT, Claude, Llama, Gemini.

🎨

Generative AI

Models that create new content — text, images (DALL·E, Stable Diffusion), audio, video, code — rather than just classifying.

How AI Engineers build with LLMs

✍️

Prompting

Write clear instructions & examples. Cheapest, fastest lever.

📚

RAG

Retrieval-Augmented Generation: look up relevant documents first, then let the LLM answer using them. Like an open-book exam.

🎓

Fine-tuning

Further train a model on your own examples to specialise its style or skills.

🦾

Agents

LLMs that plan and use tools (search, code, APIs) in a loop to finish multi-step tasks.

A pre-trained LLM is like a brilliant new graduate who has read the whole library but knows nothing about your company. Prompting = giving clear instructions. RAG = handing them the company handbook. Fine-tuning = sending them on a training course.
LLMs can hallucinate — confidently state things that are false. Always ground answers in sources, evaluate systematically, and add guardrails for safety and privacy.
End-to-End Lifecycle · Steps 9–10

From notebook to real product: MLOps

A model sitting in a notebook helps nobody. Deployment puts it where users can reach it; MLOps keeps it healthy over time.

📦

Package

Save the trained model, wrap it in an API (FastAPI / Flask), put it in a Docker container so it runs the same everywhere.

☁️

Serve

Real-time: a website asks for a price and gets it in milliseconds. Batch: score all customers overnight. Hosted on Azure ML, AWS SageMaker, GCP Vertex, or Kubernetes.

🩺

Monitor

Track accuracy, latency and cost. Watch for data drift: the world changes (new neighbourhoods, inflation) and the model slowly gets worse.

🔁

Retrain (CI/CD/CT)

Automated pipelines test code, retrain on fresh data and safely roll out new versions (A/B tests, canary releases).

🗂️

Track & version

Record every experiment, dataset version and model version (MLflow, Weights & Biases, DVC) so results are reproducible.

⚖️

Responsible AI

Check fairness across groups, explain predictions (SHAP), protect privacy, document limitations.

Training a model is like building a car. MLOps is everything after: the factory that builds it reliably, the dashboard warning lights, regular servicing, and recalls when something goes wrong.
